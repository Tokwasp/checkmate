# 검역 규정 RAG에 Rerank 적용

> 벡터 검색 상위권을 화물 수입 절차가 차지해 정작 물품 규정이 밀려나던 문제를,
> **넓게 검색 → Cohere Rerank로 재정렬 → 점수 기준으로 자르기**로 해결하고 입력 토큰을 38% 줄인 기록

---

## 1. 배경

기념품 사진을 찍으면 비전 모델이 물품(이름·분류·원재료·상태)을 판독하고, 서버가 **한국 입국 세관·검역 규정**을
Bedrock Knowledge Base에서 검색해 LLM이 `허용 / 제한 / 금지`를 판정합니다.

검색 질의는 물품 하나당 두 개입니다.

| 질의 | 예시 | 찾으려는 것 |
|---|---|---|
| 품목 질의 | `육포 육류 가공품 돼지고기 소고기 건조 가공 반입 검역` | 이 물품이 어떤 규정에 걸리는지 |
| 과태료 질의 | `육류 가공품 휴대 반입 과태료 부과기준 자진 신고` | 걸렸을 때의 과태료·신고 방법 |

기존에는 두 질의 모두 **벡터 검색 top-30**을 그대로 LLM에 넣었습니다.

## 2. 문제

### 2-1. 물품 규정이 벡터 순위에서 밀려남

검역 문서에는 여행자 휴대품 규정과 **화물 수입 절차**(컨테이너 개봉검사, 항공화물 검사 방법 등)가 섞여 있습니다.
둘 다 "소고기", "상아" 같은 단어를 공유하기 때문에, 벡터 유사도로는 화물 절차가 상위를 차지하고
실제로 판정에 필요한 조문이 한참 뒤로 밀렸습니다.

| 물품 | 판정에 결정적인 조문 | 벡터 순위 |
|---|---|---|
| 상아 조각품 | "코뿔소 뿔, 코끼리 상아 및 그 가공품을 국내로 수입(반입)하는 경우" | **11위** |
| 소고기 통조림 | "상업적으로 제조·판매되는 5kg 이하 멸균처리 통조림" | **23위** |

상아 조각품의 벡터 top-5는 뿔 검역, 동물성비료 검역, 원피 검역 같은 **화물 수입 절차**뿐이었습니다.
판정 자체는 `금지`로 맞았지만, 근거는 과태료 질의 30위에 겨우 걸린 CITES 조항이었습니다. 운 좋게 맞은 셈입니다.

### 2-2. 이를 메우려고 넓게 검색하니 토큰이 커짐

top-k를 줄이면 결정적 조문이 빠지고, 늘리면 관련 없는 청크까지 들어가 **건당 입력 토큰이 약 18,000**까지 늘었습니다.
LLM 비용 대부분이 입력 토큰이라 검색 품질과 비용이 맞물려 있었습니다.

## 3. 시도한 방법

골든셋(기대 판정을 미리 정해 둔 40종: 금지 14 / 제한 9 / 허용 17)으로 매번 같은 조건에서 판정을 다시 돌려 비교했습니다.

### 시도 1. 벡터 top-5로 그냥 줄이기 — ❌

리랭크 top-5와 벡터 top-5를 물품별로 비교하니 **겹치는 청크가 22%(44/200)** 에 불과했습니다.
상아·소고기 통조림처럼 결정적 조문이 벡터 top-5 밖에 있는 경우가 생겨 단순히 자르는 것은 답이 아니었습니다.

### 시도 2. top-30 → Cohere Rerank top-5 (품목·과태료 모두) — ⚠️

5종 샘플에서 판정은 모두 같았고 입력 토큰은 약 **10,800 → 5,700으로 절반** 가까이 줄었습니다.
하지만 위스키는 리랭크 후 **과태료 근거 청크가 빠졌습니다.**
육류·유제품의 금지 근거인 "검역증명서 미첨부 과태료" 청크는 과태료 질의 벡터 **12~13위**에 있어서, 과태료 질의까지 좁히면 빠집니다.

→ **과태료 질의는 리랭크하지 않고 그대로 두고, 품목 질의에만 리랭크를 적용**하기로 했습니다.

### 시도 3. 리랭크 점수 기준(threshold) 정하기

"상위 5개"만으로는 관련 없는 청크도 들어오기 때문에 점수 기준을 함께 걸었습니다.

- **0.30으로 시작** → 진통제·종합비타민·감기약의 "의약품 6병 한도" 표, 사과·화분 식물의 "식물 검역 안내" 같은
  판정 근거가 **0.25~0.30 구간**에 있어 잘려 나갔습니다.
- **0.25로 낮춤** → 위 근거가 모두 들어오면서도, 인형·볼펜·머그컵 같은 일반 공산품은 최고 점수가 0.15~0.28이라
  청크가 거의 들어가지 않습니다. 관련 규정이 없는 물품은 규정을 억지로 넣지 않게 됩니다.

| 물품 | 근거 청크 리랭크 점수 | 근거 내용 |
|---|---|---|
| 진통제 | 0.2619 | 의약품 총 6병 한도 표 |
| 종합비타민 | 0.2566 | 의약품·건강기능식품 수량 안내 |
| 감기약 | 0.2886 | 의약품·건강기능식품 수량 안내 |
| 화분 식물 | 0.2945 | 식물 검역 안내 |
| 사과 | 0.2991 | 식물 검역 안내 (모든 식물류 신고 대상) |
| 향수 | 0.2955 | CITES 지정 제외 대상에 향수 완제품 포함 |

### 시도 4. 후보 풀(candidate pool) 넓히기

리랭크는 **벡터 검색이 가져온 후보 안에서만** 순서를 바꿀 수 있습니다. 소고기 통조림 조문이 벡터 23위였기 때문에
후보를 top-30 → **top-50**으로 넓혀 결정적 조문이 리랭크 대상에 들어오게 했습니다.

## 4. 최종 설계

```text
            ┌─ 품목 질의 ─→ 벡터 top-50 ─→ Cohere Rerank 3.5 ─→ 점수 ≥ 0.25 중 top-5 ─┐
물품 판독 ──┤                                                                         ├─→ 중복 제거 ─→ LLM 판정
            └─ 과태료 질의 → 벡터 top-15 (리랭크 안 함) ──────────────────────────────┘
```

| 항목 | 값 | 이유 |
|---|---|---|
| 후보 풀 | 50 | 벡터 23위에 있던 조문까지 리랭크 대상에 포함 |
| 채택 기준 | 0.25 | 0.25~0.30 구간의 의약품·식물 검역 근거 보존 |
| 채택 개수 | 최대 5 | 입력 토큰 절감 |
| 과태료 질의 | 리랭크 제외 | 과태료 근거 청크가 벡터 12~13위라 좁히면 빠짐 |
| 리랭크 리전 | `ap-northeast-1` (도쿄) | Cohere Rerank 3.5가 서울 리전에 없어 별도 클라이언트 사용 |

### 구현에서 신경 쓴 점

- **장애 시 대체 경로** — 리랭크 호출이 실패해도 판정을 멈추지 않고 경고 로그를 남긴 뒤
  **벡터 상위 N개로 대신 판정**합니다. 리랭크는 품질 개선 수단이지 필수 의존성이 아니기 때문입니다.
- **리전 분리** — 리랭크 모델이 도쿄 리전에만 있어 `QuarantineReranker`가 도쿄 리전 `BedrockAgentRuntimeClient`를
  따로 가집니다. 같은 타입의 클라이언트 빈이 두 개면 주입이 모호해지므로 빈으로 노출하지 않고 리랭커 안에 넣었습니다.
- **설정으로 끄기** — 기본값을 `application.yaml`에 두어 운영 환경에 변수를 추가하지 않아도 동작하고,
  `BEDROCK_QUARANTINE_RERANK_ENABLED=false` 하나로 기존 방식으로 되돌릴 수 있습니다.
- **테스트** — 품목 질의만 리랭크되는지, 리랭크 실패 시 벡터 결과로 대체되는지 단위 테스트로 고정했습니다.

```java
/** 리랭크가 실패하면 판정을 멈추지 않고 기존 방식(벡터 상위 number-of-results개)으로 돌아간다. */
private List<String> itemChunks(String query, RetrievalFilter filter) {
    if (!reranker.isEnabled()) {
        return retrieveFor(query, filter, properties.numberOfResults());
    }
    List<String> candidates = retrieveFor(query, filter, reranker.candidatePool());
    try {
        return reranker.rerank(query, candidates);
    } catch (RuntimeException e) {
        log.warn("[quarantine-check] 리랭크 실패 — 벡터 상위 {}건으로 대신한다", properties.numberOfResults());
        return candidates.stream().limit(properties.numberOfResults()).toList();
    }
}
```

## 5. 결과

골든셋 40종 기준입니다.

| | 기존 (리랭크 미적용) | 리랭크 적용 |
|---|---|---|
| 검색 | 품목·과태료 질의 벡터 top-30 | 품목: top-50 → 리랭크 → 0.25 이상 top-5 |
| 일치 | 39 / 40 | 39 / 40 |
| 놓침 (금지인데 허용) | 0 | 0 |
| 과잉 판정 | 0 | 0 |
| **입력 토큰 (건당 평균)** | 18,371 | **11,313 (−38%)** |
| **건당 비용** (Sonnet 기준 추정) | 약 88원 | **약 61원** (리랭크 1회 포함) |

**판정 정확도는 그대로 유지하면서 입력 토큰을 38% 줄였습니다.**
비용 수치는 실험에 쓴 Sonnet 단가로 계산한 추정치이며, 운영 모델(Haiku 4.5)에서도 입력 토큰이 줄어든 비율은 같습니다.

### 판정 근거의 질이 달라짐

정확도 숫자는 같지만, **판정 근거**가 바뀌었습니다.

| 물품 | 리랭크 전 근거 | 리랭크 후 근거 |
|---|---|---|
| 상아 조각품 | [과태료 질의 30위] CITES 국제거래 금지 동물 조항 | **[품목 리랭크 1위, 0.4736]** "코끼리 상아 및 그 가공품을 국내로 반입하는 경우" |
| 소고기 통조림 | [과태료 질의 12위] 검역증명서 미첨부 과태료 표 + 프롬프트 규칙 | **[품목 리랭크 4위, 0.5342]** "5kg 이하 멸균처리 통조림" 조문 |

리랭크 전에는 품목 규정 없이 과태료 표에 기대어 판정했고, 리랭크 후에는 **해당 물품을 직접 다룬 조문**을 근거로 판정합니다.
사용자에게 보여주는 판정 사유가 규정에 실제로 근거하게 됐다는 점이 숫자보다 큰 변화였습니다.

## 6. 한계와 남은 과제

- **소고기 통조림** — 리랭크로 "5kg 이하 멸균 통조림은 확인방법 생략" 조문을 찾자 판정이 `금지 → 제한`으로 바뀌었습니다.
  골든셋 기대값(`금지`)과 달라 "금지 약화"로 집계됐지만, 찾아낸 조문 기준으로는 `제한`이 맞을 수도 있습니다.
  **골든셋 기대값 자체를 규정 원문으로 다시 검토**해야 합니다.
- 리랭크 모델이 도쿄 리전에만 있어 리전 간 호출 지연이 추가됩니다.

## 7. 참고 — 항공 보안 규정에는 왜 적용하지 않았나

같은 방식을 출국 짐의 **기내·위탁 반입 판정(항공 보안 규정)** 에도 시도했지만 넣지 않았습니다.

- 항공 판정은 여행 전체 짐을 **한 번에 묶어(batch) 판정**하는 구조라 LLM 호출 수가 적습니다.
  top-30 → top-10으로 줄여도 **리랭크 요금이 아낀 토큰값과 비슷해** 비용 절감이 거의 없었습니다.
- 반면 검역 판정은 **물품 하나당 한 번** 호출하고, 문서에 화물 절차가 섞여 있어 리랭크로 얻는 검색 품질 개선이 컸습니다.

같은 기법이라도 **호출 구조와 문서 특성에 따라 효과가 다르므로**, 골든셋으로 실측해 적용 범위를 정했습니다.
